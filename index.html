Architecture & key decisions (for the demo walkthrough)

Pipeline: transcripts → timestamped chunks (1 turn = 1 chunk, 21 total) → TF-IDF index → cosine retrieval → extractive answer + citation

Model choice: no generative model in the default path — deterministic TF-IDF + synonym expansion runs fully offline in the browser. An LLM is an optional summarizer layered on top, and only ever receives retrieved chunks with an instruction to quote verbatim (see README).

Citations / timestamps: chunking preserves {expert, speaker, mm:ss} metadata; the UI renders every claim as answer + exact quote + [Name · mm:ss]. Quote strings are never reworded.

Anti-hallucination: (1) extractive-only answers, (2) relevance threshold with explicit “no evidence” fallback, (3) curated guide answers pinned to single chunk IDs, (4) disagreement section shows all sides with quotes instead of averaging them away.

Scale 3 → 30+ transcripts: same chunk schema; replace in-browser TF-IDF with embeddings (e.g. bge / e5) + a vector store (FAISS / pgvector), add speaker diarization + timestamp alignment for audio, dedupe near-identical turns, cache per-question answers, and add an eval harness (citation precision: % of quotes that are exact substrings; answer recall per guide question).
